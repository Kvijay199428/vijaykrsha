# Compression

How `vijaykrsha.online` compresses responses, and the rules that keep it from
breaking clients or wasting CPU.

## The one rule: one compression owner per hop

Each connection in the request path has exactly one component responsible for
choosing a `Content-Encoding`. Layers do not stack on the same response.

```
Browser ──► Cloudflare edge ──► origin (nginx / FastAPI)
             │                    │
             │ owns browser-      │ owns origin-side
             │ facing encoding    │ encoding (gzip only)
             ▼                    ▼
        br / zstd / gzip     gzip (static + dynamic)
```

- **Cloudflare edge** negotiates `br` / `zstd` / `gzip` with the visitor. This is
  the primary browser-facing compressor for both the site and the API host.
- **Origin nginx** (`nginx.conf`, `nginx.ssl.conf`, `nginx.api-gateway.prod.conf`)
  owns gzip on the origin side. Because nginx never re-encodes a body that
  already carries `Content-Encoding`, adding a second layer here is safe only if
  the upstream did not already encode.
- **FastAPI is intentionally uncompressed.** See [Backend decision](#backend-decision).

## Method matrix

These are **not** interchangeable HTTP encodings. Only the first column is ever
sent as a `Content-Encoding` to a browser.

| Method            | Role                                                       | Sent to browsers?            |
| ----------------- | ---------------------------------------------------------- | ---------------------------- |
| `br` (Brotli)     | Browser-facing encoding                                    | Yes, via Cloudflare edge     |
| `zstd` (Zstandard)| Browser-facing encoding                                    | Yes, via Cloudflare edge     |
| `gzip`            | Origin + browser-facing encoding; precompressed sidecars   | Yes                          |
| `deflate`         | Browser-facing encoding (rarely worth it)                  | Optional                     |
| Zopfli            | Produces gzip-compatible bytes at build/benchmark time     | Sent as `gzip`, never `zopfli` |
| LZ4               | Internal/benchmark only                                    | Never                        |
| Snappy            | Internal/benchmark only                                    | Never                        |
| LZMA / XZ         | Archive/benchmark only                                     | Never                        |
| bzip2             | Archive/benchmark only                                     | Never                        |
| identity          | Uncompressed fallback                                      | Yes                          |

Never emit `Content-Encoding: lz4`, `snappy`, `xz`, `bzip2`, or `zopfli` — no
browser decodes them, and the response body would be corrupt.

## Frontend assets (Vite)

Precompressed **gzip** sidecars are opt-in via `VITE_PRECOMPRESS=1`
(`vite.config.ts` → `vite-plugin-compression2`, gzip level 9, 1 KB threshold).

- **Docker / dev builds** set the flag, so `dist/` contains `*.gz` next to the
  originals and nginx serves them via `gzip_static` instead of compressing per
  request.
- **Cloudflare Pages builds** leave the flag unset. Pages does not serve sidecar
  files, and the edge compresses on the wire, so sidecars would be dead weight.
  `cloudflare.py` also refuses to include `*.gz`/`*.br`/`*.zst` in the upload zip.
- **Brotli/zstd sidecars are deliberately not generated for Vite-hashed assets.**
  Stock `nginx:1.27-alpine` compiles `http_gzip_static_module` but neither
  `ngx_brotli` nor a zstd module, so `gzip_static` cannot serve `.br`/`.zst`.

Eligibility rules live in one place, `scripts/compression-rules.mjs`, shared by
the build and the verifier.

### Favicon / icon compression (separate pipeline)

Favicon, icon, apple-touch-icon, and `site.webmanifest` files **do** get
`.gz` and `.br` sidecars, generated by `scripts/precompress-icons.mjs`
(runs post-build in the Dockerfile). These are **not** served via `gzip_static`;
they use a dedicated nginx `location` block with `Accept-Encoding`
content-negotiation:

```
map $http_accept_encoding → $icon_suffix / $icon_encoding

location ~ ^/(favicon\.|apple-touch-icon|icon\d+|site\.webmanifest) {
    gzip off;
    gzip_static off;
    try_files $uri$icon_suffix $uri =404;
    add_header Content-Encoding $icon_encoding;
    add_header Vary "Accept-Encoding" always;
    types { ... application/manifest+json webmanifest; }
}
```

The `map` inspects the client's `Accept-Encoding` header during the HTTP
handshake and picks the best match (priority: brotli → gzip → identity).
`try_files` then serves the compressed sidecar if it exists, or falls back to
the uncompressed original. This gives the origin brotli capability for icons
without requiring `ngx_brotli`.

> [!IMPORTANT]
> **zstd was removed from the icon negotiation maps** (2026-10-19). The build
> never produces `.zst` sidecars (no `fzstd` dependency), so the map could
> select `.zst`, `try_files` would fall back to the raw file, server-level
> `gzip_static` would serve the `.gz` with its own `Content-Encoding: gzip`,
> and the location's `add_header` emitted a second `Content-Encoding: zstd`.
> Two conflicting encodings → every icon failed in browsers with
> `ERR_CONTENT_DECODING_FAILED`. `gzip_static off;` inside the location and
> the zstd removal together prevent the whole class. If `.zst` sidecars are
> ever added (via `fzstd`), re-add zstd to the maps **and** keep a build gate
> that asserts every advertised sidecar exists.
>
> The `types` block in the location is also mandatory: nginx's default MIME
> table has no `.webmanifest` entry (served as `application/octet-stream`,
> which browsers refuse to parse as a manifest), and a `types` block REPLACES
> the inherited table — so png/svg/ico must be listed explicitly too.

**Cloudflare Pages** does not use these sidecars — the edge compresses on the
wire — so `cloudflare.py` strips them from the upload zip.

### Build-mode verification

```bash
# Docker / origin mode: sidecars must exist and decode to the originals.
VITE_PRECOMPRESS=1 npm run build
npm run precompress:icons               # generate icon .gz/.br sidecars (.zst only if fzstd installed)
npm run verify:compress -- --mode=nginx # writes dist/compression-manifest.json

# Pages mode: no sidecars may be present.
npm run build
npm run verify:compress -- --mode=pages
```

## nginx

`gzip_static on;` and `gzip_vary on;` are set on the frontend vhosts
(`nginx.conf`, `nginx.ssl.conf`). Confirm the module is compiled into the image
before relying on it:

```bash
docker run --rm nginx:1.27-alpine nginx -V 2>&1 | tr ' ' '\n' | grep gzip_static
```

If `http_gzip_static_module` is absent, remove `gzip_static on;` (nginx refuses
to boot on directives its binary does not implement) — dynamic `gzip` still works.

The API gateway (`nginx.api-gateway.prod.conf`) keeps `gzip on; gzip_vary on;`
and inherits the single-owner rule.

## Cloudflare Compression Rules

Configure in the dashboard (Rules → Settings → Compression Rules), not in
`cloudflare.yml` (that file is Pages project config; zone rules do not belong in it):

1. Prefer **Zstandard → Brotli → gzip**.
2. Keep a **gzip fallback** enabled.
3. Scope the rule to text MIME types (`text/*`, `application/json`,
   `application/javascript`, `image/svg+xml`, …), not to file extensions.

Verify the result in the browser Network panel or:

```bash
npm run check:encoding -- --target=https://vijaykrsha.online/
```

### Observed edge behaviour (Cloudflare)

Measured against the live zone on 2026-10-11:

| Response                       | `Content-Encoding` (client offered br,zstd,gzip) | `Vary`                       |
| ------------------------------ | ------------------------------------------------ | ---------------------------- |
| `/` (no-store document)        | `br` / `gzip` / none                             | absent                       |
| `/assets/*.js|css` (cache MISS)| `br` / `gzip` / none                             | `accept-encoding`            |
| `/assets/*.js|css` (cache HIT) | `br` / `gzip` / none                             | **absent**                   |

So the edge negotiates correctly per client (the important safety property) but
does **not** reliably emit `Vary: Accept-Encoding` on cached variants. We
therefore do not force a `Vary` header into `public/_headers` — Cloudflare
already adds it on misses, and duplicating it would emit the header twice. Treat
`Vary` at the edge as informational; validate it at the origin (nginx) with
`--require-vary`.

## Backend decision

**FastAPI does not compress.** Every API response already passes through the
nginx gateway and the Cloudflare edge, so a backend layer would be a third
compressor on the same bytes — redundant CPU and an extra BREACH surface on
`/admin/api/*`.

This stays true until one of these becomes real:

1. A measurable bandwidth problem on a public JSON endpoint (`/vks/*`), **and**
2. The Pages Function probe below confirms the proxy does not double-compress.

If both hold, add a pure-ASGI middleware (not `GZipMiddleware`) that parses
`Accept-Encoding` with q-values, honors a minimum size, skips already-encoded
bodies and streaming responses, excludes `/admin/api/*` and `/ws/`, and appends
(never overwrites) `Vary: Accept-Encoding`.

### Pages Function probe (prerequisite for any backend compression)

`functions/api/[[path]].ts` forwards `request.headers` verbatim and rebuilds the
response. The Workers runtime may transparently decode an upstream
`Content-Encoding`, which would make an origin-side `Content-Encoding` lie about
the bytes on the wire.

Probe before enabling backend compression:

```bash
# Ask the Function for a known compressible payload and inspect the headers.
curl -sI -H 'Accept-Encoding: gzip, br' https://vijaykrsha.online/api/... 
curl -sI            https://api.vijaykrsha.online/vega/api/...
```

Then decide one of:

- **strip** `Accept-Encoding` toward the origin (let the edge encode on return), or
- **forward** it and keep the origin uncompressed.

Never leave it ambiguous: a mismatched `Content-Encoding` and body is a hard bug.

## Automated checks

| Script                              | What it proves                                                        |
| ----------------------------------- | --------------------------------------------------------------------- |
| `npm run verify:compress`           | Sidecars exist + decode (nginx mode); none leak into Pages (pages mode) |
| `npm run precompress:icons`         | Generates `.gz`/`.br` sidecars for favicon/icon/manifest files (`.zst` only if `fzstd` is installed) |
| `npm run check:encoding`            | No encoding is ever sent that the client did not offer; sensitive admin API uncompressed + `no-store`. Add `--require-vary` to assert `Vary` at your own origin. |
| `npm run bench:compress`            | Offline size/CPU of every algorithm, incl. benchmark-only ones        |

## Deploy checklist

1. Baseline headers/asset sizes before the change.
2. Build both modes; run `verify:compress` for each.
3. Run `precompress:icons` (Docker builds do this automatically).
4. Deploy origin (nginx) and confirm `gzip_static` served a `.gz` (`Content-Encoding: gzip`).
5. Verify icon content-negotiation: request `/favicon.svg` with `Accept-Encoding: br`
   and confirm `Content-Encoding: br` in response.
6. Configure Cloudflare Compression Rules; confirm `br`/`zstd` reach a real browser.
7. `npm run check:encoding` against the deployed hosts.
8. Regression: admin login → refresh → logout, CSRF, attachment download
   (streaming), and `Cache-Control: no-store` on `/admin/api/*`.
9. Keep a rollback to the previous compression policy.
